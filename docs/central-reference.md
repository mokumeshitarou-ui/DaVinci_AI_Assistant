# 中央フォルダーから同じ編集基準を使う

各PCの毎回の入口は、指定された中央PCの既存共有内にある「編集共通」のREADME。GitHubは共通手順の継続履歴・保存先とし、中央の配布済み固定版を実作業で参照する。中央PC名・共有パスは各PCの参照設定に置き、この公開文書へ内部パスを書かない。

## 開始・再開と次の編集ブロック

1. 中央の `CURRENT.json` を読み、配布元ホスト、使用commit、releaseへの相対パス、manifestのSHA-256を照合する。既存の認証済み経路を使い、新しいログインや共有設定変更を自動で行わない。
2. `releases/<commit>/manifest.json` にある対象文書のSHA-256を確認し、使用版を既存案件メモへ固定する。取得済みの同じ版は再利用し、各カットで全資料を読み直さない。
3. 今の案件に必要な節だけ読み、次の許可済み編集ブロックから適用する。起動中の作業・アプリを再スタートせず、進行中のブロックを新版へ無条件に切り替えない。
4. 中央へ接続できなければ、取得・照合済みの同じcommitのローカル固定版を補助として使う。「中央最新版未確認」と使用版を明記し、独立した許可済み作業を続ける。キャッシュを別の正本として改訂しない。

最新ユーザー指定・案件のNG・承認済み顔と色・現在の起動や切替の権限を保持する。各PCの固有差分を中央の一般文書で上書きせず、関連する差分だけ照合する。モデル名・字幕件数・文書の配布成功を、本文や実映像の品質合格に置き換えない。

## 中央版の更新

GitHubの既存headと他担当の変更を照合し、同じ正本へ限定差分を非強制で保存する。コミットと変更本文を読戻した後、中央へ新しい固定版を追加する。manifestにはrepository、commit、相対パスごとのサイズとSHA-256を記録し、文書が揃って一致してからCURRENTを切り替える。旧版は保持する。

各PCが中央CURRENTとmanifestを実際に読み、使用ファイルのハッシュが一致した結果を配布証拠に残す。単なるファイル送付や入口更新と、担当者の読了・案件への適用・品質検収は別に報告する。未知のPC経路を推測せず、そのPCの未接続を明記する。
