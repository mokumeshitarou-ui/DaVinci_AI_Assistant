# カットごとの字幕と品質検収

## ユーザーの必須条件（2026-10-08 最終指定）

**目標は1映像カットに1字幕以上。適切な字幕をどうしても考えられないカットに限り省略を認め、字幕対応率85％以上を許容下限にする。**

100カットなら、原則100カットすべてに字幕を付け、やむを得ない省略がある場合も85カット以上には字幕を付ける。1カット内に複数の説明が必要なら複数字幕にする。85％を最初からの作業目標や一律の打切り地点にしない。省略したカットと具体的な理由を既存台帳に残す。

通常編集70〜80点はこの字幕条件を省く理由にならない。編集担当・PC・モデルが違っても同じ条件を使う。前の「未字幕0件だけを許可」の記述は、この最終指定で更新する。

## 対応率の数え方

- 分母N：現在の本編で有効な映像カット数。調整クリップ、装飾、非表示候補を混ぜない。重ね映像は実際のショットとの対応を明記する。
- 分子M：そのカットに対応する有効な字幕が1件以上ある映像カット数。
- 対応率：M / N。許容下限は **M >= ceil(0.85 × N)**。小数の切捨てで85％未満を合格にしない。
- 字幕総数Sは別に記録する。同じカットへ複数字幕を集めても、他の無字幕カットの代わりにはならない。前カットの字幕がはみ出すだけでも対応済みにしない。
- Mが下限以上でも、未確認・未処理・手間を理由に残した無字幕カットがあれば、その工程は未完了。許容するのは適切な字幕を検討したうえでの省略である。

## 各カットに何を書くか

映像を確認し、そのカットの動作、対象、変化が分かる具体的な短文を付ける。料理名だけに偏らず、仕込み、材料を取り出す、洗う、切る、量る、混ぜる、包む、加熱、盛り付け、配膳、器の準備、補充、台拭き、客席、店外、片付け等を対象にする。外観や手待ちも見える事実に合わせる。

料理名・食材名・価格・会話が未確認なら、確実に見える動作・状態で字幕を検討する。不明な名称や味、作り手の気持ち、目的、客の感想を推測で埋めない。発言字幕の実聴待ちを、その場面の動作説明まで止める理由にしない。

連続する同じ動作でも、前後の工程・対象・変化を見て自然な本文を検討する。無理に違う事実を作らず、適切な同文の再表示も認める。それでも適切な字幕が思いつかない場合に限り、省略理由を残す。対応率を上げるために無断で映像を削らない。

## Resolveでの作業単位

1. 現在のPJ/TLと有効な本編映像カットを一括取得する。実素材のカットを数える。
2. 既存のカット台帳へ、カットID、ソース範囲、TL範囲、対応字幕ID、本文、表示範囲、根拠、確認状態を接続する。
3. 字幕なしカットを全件抽出し、確認済みの動作から追加する。既存の有効字幕を保持する。同じ処理の再実行で二重字幕を作らない。省略はカットごとに理由を残し、未確認・未処理と区別する。
4. 標準は短い名詞句・具体的動作、原則1行17字以内、句読点なし、半角空白で区切り、数字は全角。表示開始は説明している動作に合わせる。カット頭15フレーム後は、動作が冒頭から始まる場合の目安であり固定値ではない。動作が始まる前に字幕が消える配置は直す。表示2〜7秒・1秒4字を目安にする。短いカットは読める本文・表示区間へ調整する。表示不能を隠すためにダミー字幕を置かない。
5. 保存して実TLを読戻し、カット単位で対応と有効表示を照合する。タイトル用Fusion等の既存様式も本文と有効表示を確認する。
6. 各字幕の実表示・カットとの内容一致・可読性・字幕同士の重なり・境界残り・顔や料理へのかぶりを確認する。中央静止画1点では動作同期や全表示期間の検証済みとしない。

## 完了判断とHTML

既存HTMLに、全カット数N、字幕対応カット数M、対応率、許容下限ceil(0.85N)、字幕総数S、理由付き省略カット、未確認・未処理カットを表示する。カットIDごとの本文・時刻・省略理由を見返せるようにする。計画・SRTだけの件数と、Resolve反映・保存・読戻し済みの件数を分ける。

進捗は「映像Nカット／字幕対応Mカット（率）／字幕S件／理由付き省略Kカット／未処理Uカット／実表示検収Lカット」の形で返す。不明なら不明と記す。

完了には、対応率85％以上、各省略の適切な理由、対応不明・未処理0件、本文と表示の検収が必要。件数条件を満たしただけで内容・色・顔・原音の品質を合格にしない。未検証を全体完成としない。

この文書の改定だけでは既存案件を検収済みにしない。各既存担当が現在のTLを監査し、不足を同じ作業TLへ反映する。新規Agent・席・アプリ・レンダーは自動で起こさない。
