# カットごとの字幕と品質検収

## ユーザーの必須条件（2026-10-08 再確認）

**1映像カットに最低1字幕。必要なら1カットに複数字幕。**

通常カット・構成・字幕の実用完成70〜80点は、この条件を省く理由にならない。「字幕は件数で決めない」「料理名が分かるカットだけ」「同じ動作だから説明不要」と解釈して字幕なしカットを残さない。編集担当・PC・モデルが違っても同じ条件を使う。

## 各カットに何を書くか

映像を確認し、そのカットの動作、対象、変化が分かる具体的な短文を付ける。料理名だけに偏らず、仕込み、材料を取り出す、洗う、切る、量る、混ぜる、包む、加熱、盛り付け、配膳、器の準備、補充、台拭き、客席、店外、片付け等を対象にする。外観や手待ちも見える事実に合わせる。

料理名・食材名・価格・会話が未確認なら、確実に見える事実で字幕を作る。不明な名称や味、作り手の気持ち、目的、客の感想を推測で埋めない。発言字幕の実聴待ちを、その場面の動作説明まで止める理由にしない。

連続する同じ動作でも各カットに字幕を付ける。前後の工程・対象・変化を見て自然な本文にする。映像に新たな事実がなければ無理に違う事実を作らず、適切な同文の再表示も認める。字幕を減らすために無断で映像を削らない。

## Resolveでの作業単位

1. 現在のPJ/TLと有効な本編映像カットを一括取得する。実素材のカットを数え、テロップ・調整クリップ・非表示候補を混ぜない。重ね映像は実際のショットとの対応を明記する。
2. 既存のカット台帳へ、カットID、ソース範囲、TL範囲、対応字幕ID、本文、表示範囲、根拠、確認状態を接続する。
3. 字幕なしカットを全件抽出し、確認済みの動作から追加する。既存の有効字幕を保持する。同じ処理の再実行で二重字幕を作らない。
4. 標準は短い名詞句・具体的動作、原則1行17字以内、句読点なし、半角空白で区切り、数字は全角。通常開始はカット頭15フレーム後、表示2〜7秒・1秒4字を目安にする。短いカットは読める本文・表示区間へ調整し、最低1字幕の条件を無視しない。
5. 保存して実TLを読戻し、カット単位で対応を照合する。タイトル用Fusion等を使う既存様式も本文と有効表示を確認する。
6. 各字幕の実表示・カットとの内容一致・可読性・字幕同士の重なり・境界残り・顔や料理へのかぶりを確認する。中央静止画1点では動作同期や全表示期間の検証済みとしない。

## 完了判断とHTML

**字幕なし映像カット0、対応不明0**を必要条件にする。字幕総数がカット数以上というだけでは合格にしない。字幕がある一部のカットに複数件が集中しても、他の未字幕カットの代わりにはならない。前カットの字幕がはみ出すだけでもそのカットの完了にはしない。

既存HTMLに、全カット数、字幕が対応したカット数、字幕なしカット数、字幕総数、未検収数、カットIDごとの本文と時刻を出す。計画・SRTだけの件数と、Resolve反映・保存・読戻し済みの件数を分ける。

進捗は「映像Nカット／字幕対応Mカット／未字幕Kカット／字幕S件／実表示検収Lカット」の形で返す。不明なら不明と記す。件数の合格は内容・色・顔・原音の品質合格と別に扱う。未検証を全体完成としない。

この手順の改定だけでは既存案件を検収済みにしない。各既存担当が現在のTLを監査し、不足を同じ作業TLへ反映する。新規Agent・席・アプリ・レンダーは自動で起こさない。
