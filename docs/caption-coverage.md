# カットごとの字幕と品質検収

## ユーザーの必須条件（2026-10-08 最終指定）

**目標は1映像カットに1字幕以上。適切な字幕をどうしても考えられないカットに限り省略を認め、字幕対応率85％以上を許容下限にする。**

100カットなら、原則100カットすべてに字幕を付け、やむを得ない省略がある場合も85カット以上には字幕を付ける。1カット内に複数の説明が必要なら複数字幕にする。1カット1本で打ち切る条件ではない。85％を最初からの作業目標や一律の打切り地点にしない。省略したカットと具体的な理由を既存台帳に残す。

通常編集70〜80点はこの字幕条件を省く理由にならない。編集担当・PC・モデルが違っても同じ条件を使う。前の「未字幕0件だけを許可」の記述は、この最終指定で更新する。

## 対応率の数え方

- 分母N：現在の本編で有効な映像カット数。調整クリップ、装飾、非表示候補を混ぜない。重ね映像は実際のショットとの対応を明記する。
- 分子M：そのカットに対応する有効な字幕が1件以上ある映像カット数。
- 対応率：M / N。許容下限は **M >= ceil(0.85 × N)**。小数の切捨てで85％未満を合格にしない。
- 字幕総数Sは別に記録する。同じカットへ複数字幕を集めても、他の無字幕カットの代わりにはならない。前カットの字幕がはみ出すだけでも対応済みにしない。
- Mが下限以上でも、未確認・未処理・手間を理由に残した無字幕カットがあれば、その工程は未完了。許容するのは適切な字幕を検討したうえでの省略である。

## 各カットに何を書くか

動画観察のイベント名や解析応答のcaptionは、動作と区間を拾うための候補として使う。最終字幕は、前後の映像を含む編集ブロックと、撮影メモ・会話・店舗調査をまとめて読み、別途文章を編集して確定する。短い観察ラベルを各カットへ流し込むだけで終えない。

本文は、対象と動作・状態変化が伝わる自然な文を軸にする。短い名詞句を既定にせず、体言止めは店名・料理名の提示など効果がある場面で使う。語尾へ「する」を足すだけの機械修正や、全字幕の体言止めをゼロにするノルマにはしない。仕込み、調理、提供、清掃、準備、客席、店外、片付け等で実際に見える内容を伝える。

本編一式では、店について自主的に調べる工程を含める。まず撮影メモ、取材会話、店内掲示、既存の店語彙・調査を確認し、公式発信や根拠の明らかな取材記事を調べる。確認できた店の背景、技法、料理情報を、関連する工程・料理の場面へ取り入れる。映像の実況だけ、または調査情報だけに偏らせない。部分修正では関連する主張の確認に絞り、変更のない店全体の再調査を始めない。

情報の根拠は既存plan・店語彙・HTMLの形式へ接続する。出典URLまたは撮影メモ・会話・掲示の参照と素材内時刻、確認できた事実、撮影時点への適用可否、対象カットIDを残す。現在のWeb情報を撮影当時の事実へ無条件に置き換えず、価格は撮影時のメニュー・取材資料で確かめる。店の一般的な技法の説明と、当該カットに映る動作の根拠を区別する。

料理名・食材名・価格・会話が未確認なら、確実に見える動作・状態で字幕を検討する。不明な名称や味、作り手の気持ち、目的、客の感想を推測で埋めない。会話は原音を確認した発言ごとに、意味と前後関係を保って字幕にする。長い会話を「〜について聞く」等の話題見出し1本で字幕完成にしない。聞き取れない部分だけを未確定にし、確認済みの発言や独立した動作説明は進める。仮の案内文と発言字幕の完成を区別する。

1カットずつ孤立して書かず、工程ブロックをまとめて起こしてから各カットの表示範囲へ割り当てる。対象・工程のつながり、主語や指示語、情報の重複、前後で矛盾する文がないか通して読む。「続いて」「その間」「この鍋」などで、未確認の撮影順・同時性・同じ食材や鍋を作らない。同じ動作の継続は適切な同文の再表示も認め、別の事実を無理に作らない。省略は前記条件に従って理由を残し、対応率を上げるために無断で映像を削らない。

Astraは文章・情報の裏付け・ブロックの流れを監督し、実装担当へ対象カットと具体的な修正を返す。指定されたSolが実反映・保存・読戻しを担当する。モデルとeffortは現在の案件指定を守り、モデル名だけで品質を保証しない。本文の根拠と文脈の検収結果は既存plan・HTMLへ残し、独立した全件チェックリストを増設しない。

## Resolveでの作業単位

1. 現在のPJ/TLと有効な本編映像カットを一括取得する。実素材のカットを数える。
2. 既存のカット台帳へ、カットID、ソース範囲、TL範囲、対応字幕ID、本文、表示範囲、根拠、調査情報の撮影時点への適用、確認状態を接続する。
3. 字幕なしカットと、観察ラベルのまま・文脈の断絶・会話が見出しだけになっている区間を抽出し、該当する編集ブロックの本文を整える。既存の有効字幕を保持する。同じ処理の再実行で二重字幕を作らない。省略はカットごとに理由を残し、未確認・未処理と区別する。
4. 本文は前記の自然な文を基本とし、17字・1行は可読性の目安とし、意味を壊して一律に短縮しない。会話や情報が長い場合は、発言・意味のまとまりごとの複数字幕や必要な改行を既存様式で使う。句読点なし、半角空白で区切り、数字は全角。表示開始は説明している動作に合わせる。カット頭15フレーム後は、動作が冒頭から始まる場合の目安であり固定値ではない。動作が始まる前に字幕が消える配置は直す。表示2〜7秒・1秒4字を目安にする。短いカットは読める本文・表示区間へ調整する。表示不能を隠すためにダミー字幕を置かない。
5. 保存して実TLを読戻し、カット単位で対応と有効表示を照合する。タイトル用Fusion等の既存様式も本文と有効表示を確認する。
6. 編集ブロックを通して文章・情報の根拠・前後のつながりを検収し、各字幕の実表示・カットとの内容一致・可読性・字幕同士の重なり・境界残り・顔や料理へのかぶりを確認する。中央静止画1点では動作同期や全表示期間の検証済みとしない。

## 完了判断とHTML

既存HTMLに、全カット数N、字幕対応カット数M、対応率、許容下限ceil(0.85N)、字幕総数S、理由付き省略カット、未確認・未処理カットを表示する。カットIDごとの本文・時刻・省略理由を見返せるようにする。計画・SRTだけの件数と、Resolve反映・保存・読戻し済みの件数を分ける。

進捗は「映像Nカット／字幕対応Mカット（率）／字幕S件／理由付き省略Kカット／未処理Uカット／実表示検収Lカット」の形で返す。不明なら不明と記す。

完了には、対応率85％以上、各省略の適切な理由、対応不明・未処理0件、本文と表示の検収が必要。対応率が100％でも、文章・情報の裏付け・前後のつながり・会話の内容が未検収なら字幕品質は未完了。件数条件を満たしただけで内容・色・顔・原音の品質を合格にしない。未検証を全体完成としない。

この文書の改定だけでは既存案件を検収済みにしない。各既存担当が現在のTLを監査し、不足を同じ作業TLへ反映する。新規Agent・席・アプリ・レンダーは自動で起こさない。
