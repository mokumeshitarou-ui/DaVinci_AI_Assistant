# 実編集のモデルと設定

ユーザー指定（2026-10-07）：aniya・sonobe・natsumi・harutoの実編集は **gpt-6.1-sol / high**。監督・検収は **gpt-6-astra / max**。通常編集は実用完成70〜80、顔・色は承認基準で検収し、モデルの名前を品質合格の根拠にしない。

## 共通の編集用プロファイル

プロファイル名は `mokumeshi-editor`。各PCの標準CodexホームとOrca管理ホームへ、次の内容を配置する。

```toml
model = "gpt-6.1-sol"
model_reasoning_effort = "high"
```

[OpenAI公式の構成リファレンス](https://learn.chatgpt.com/docs/config-file/config-reference)と実CLIのヘルプに従い、プロファイルは利用する `CODEX_HOME` 直下の `mokumeshi-editor.config.toml` に置く。既存の他用途・監督用設定へ編集モデルを上書きしない。

このプロファイルは明示して選ぶ必要がある。配置しただけでは現在稼働中の席のモデルは変わらない。復帰が許可された既存編集セッションでは、正しいセッションを指定した `codex --profile mokumeshi-editor resume <session-id>` が選択例になる。これは起動や復帰の新たな許可ではなく、現在の案件にある新規席・Agent・サービス起動、再起動、重複実行の禁止は維持する。

既存セッションへ継続メッセージを渡す経路でも、モデルとeffortの明示設定を使う。既存メッセージの重複投入を避ける。共通手順の指示文だけから実稼働モデルを断定せず、実行経路の設定と担当の実応答を読み戻す。

## 再開時に確認すること

1. 現在の担当を実編集と監督・検収に分ける。別担当の作業を重複実行しない。
2. 実編集の実効モデルが `gpt-6.1-sol`、effortが `high` であることを確認する。CLIオプションやアプリ側の明示選択が別の値なら、設定ファイルの存在だけで合格にしない。
3. 使用する実ホームの公式モデル一覧で、指定モデルとhighの対応を確認する。別ホームの古いキャッシュだけで利用不可と断定しない。利用できないときに別モデルへ黙って代替しない。
4. 正本の[編集手順](editing-playbook.md)から、未反映の1ブロックをカット・原音・字幕・Resolve保存・読戻しまで進める。
5. Astraは実反映の根拠と該当工程の品質を検収する。共通手順の訂正は[更新方法](../CONTRIBUTING.md)に従い、毎回同じGitHubへ保存する。
